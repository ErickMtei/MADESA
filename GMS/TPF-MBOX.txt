#--------------EMAIL LIMITS
To limit outgoing emails on an iRedMail server, the standard and cleanest way is using its built-in policy daemon: iRedAPD. Postfix relies on helper daemons like iRedAPD to handle time-windowed rate limits.

Step 1: Enable the throttle Plugin in iRedAPD
nano /opt/iredapd/settings.py
Find the plugins = [...] section and add 'throttle' to the active plugins:
plugins = ["greylisting", "throttle", "reject_sender_login_mismatch"]

Step 2: Ensure Postfix Relays Mail to iRedAPD

Check /etc/postfix/main.cf to ensure iRedAPD checks outgoing messages.
Under smtpd_recipient_restrictions, confirm the policy service is present:

smtpd_recipient_restrictions =
    ...
    check_policy_service inet:127.0.0.1:7777
    ...

Step 3: Insert the Throttling Rule in the Database
iRedAPD reads rate limits directly from its SQL database (iredapd).

mysql -u root -p
USE iredapd;

Option A: Global Limit for ALL Users (Server-wide)
Limits every user on the server to 10 emails per 3600 seconds (1 hour):

INSERT INTO throttle (account, kind, priority, period, max_msgs) 
VALUES ('@.', 'outbound', 0, 3600, 10);

(Note: @. acts as a global wildcard catch-all).

Option B: Per-Domain Limit
Limits every user under @yourdomain.com to 10 emails per hour:

INSERT INTO throttle (account, kind, priority, period, max_msgs) 
VALUES ('@yourdomain.com', 'outbound', 60, 3600, 10);

Option C: Per-User Limit
INSERT INTO throttle (account, kind, priority, period, max_msgs) 
VALUES ('user@yourdomain.com', 'outbound', 100, 3600, 10);

Step 4: Restart Services

Apply changes by restarting both the iRedAPD service and Postfix:

systemctl restart iredapd
systemctl restart postfix

Step 5: How to Test and Verify
tail -f /var/log/maillog
# Or on systemd systems:
journalctl -u postfix -f

Verification: You should see a rejection message stating

#--View active limits:
SELECT account, kind, period, max_msgs FROM iredapd.throttle;

#--Remove/Delete a limit:

DELETE FROM iredapd.throttle WHERE account='@.';

#---TO ALLOW SPECIFC USERS TO SEND MANY EMAILS THE REST NO:
iRedAPD uses a priority system when evaluating throttle rules. Rules with a higher priority integer override general rules with a lower priority.

To apply a limit to everyone except a few specific accounts, set a global rule (priority 0) and per-user override rules (priority 100 or setting max_msgs = 0 for unlimited).

Step 1: Log in to the iRedAPD Database
mysql -u root -p
USE iredapd;

Step 2: Apply Rules
1. Set the Global Limit (Everyone)
Set the baseline rate limit for all accounts on the server to 10 emails per hour (Priority 0):
INSERT INTO throttle (account, kind, priority, period, max_msgs) VALUES ('@.', 'outbound', 0, 3600, 33);

2. Set Exemption/Override Rules (Except Few)
Choose one of the following approaches for your VIP/exempt users:

Option A: Give specific users a higher limit (e.g., 500 emails/hour)
Set priority = 100 so iRedAPD applies this rule instead of the global rule for this user:

INSERT INTO throttle (account, kind, priority, period, max_msgs) VALUES ('vipuser@yourdomain.com', 'outbound', 100, 3600, 500);

Option B: Make specific users UNLIMITED
Setting max_msgs = 0 with higher priority disables rate limiting for that user entirely:

INSERT INTO throttle (account, kind, priority, period, max_msgs) VALUES ('boss@yourdomain.com', 'outbound', 100, 3600, 0);

Step 3: Restart iRedAPD
systemctl restart iredapd

Step 4: Verify Your Rules

Check all active throttle rules ranked by priority:
SELECT account, kind, priority, period, max_msgs FROM iredapd.throttle ORDER BY priority DESC;

#---TO LIMIT THE MAXIMUM NUMBER OF RECIPIENTS PER SINGLE EMAIL 
To limit the maximum number of recipients per single email message (to prevent spam bursts), you can configure Postfix's built-in smtpd_recipient_limit setting or enforce it via iRedAPD's recipient_limit plugin for per-account granular rules.

Option 1: Global Postfix Limit (Quickest & Easiest)
If you want a server-wide rule restricting any user from adding more than a specific number of recipients (e.g., 10 recipients per email):
1. Open Postfix configuration:
nano /etc/postfix/main.cf

2. Add or update the smtpd_recipient_limit directive:
smtpd_recipient_limit = 10

3. Reload Postfix to apply:
postfix reload

How it works: If a user attempts to send a message to 11 recipients at once, Postfix immediately drops/rejects the message with a standard 5xx SMTP response (Too many recipients).

Option 2: iRedAPD Plugin (Granular / Per-User Limits)

If you need finer control—such as exempting certain accounts from the recipient limit while restricting everyone else—use iRedAPD's built-in recipient_limit plugin.
